# 원칙(Propensity) 페이지 UI 정리 + 사이드바 ‘계정’ 버튼 제거

## 1. 배경 및 목적

- 원칙(Propensity) 페이지에서 불필요한 입력 섹션/버튼을 제거하고, 화면 폭/정렬을 더 단정하게 맞추고자 함
- 하단 액션 영역을 단순화(저장 1개만)하고, 저장 조건(비율 합계 100%)을 만족하지 않으면 저장 불가하도록 UX를 강화
- 사이드바의 ‘계정’ 메뉴 항목은 제거하되, 하단 `/account` 사용자 버튼은 유지하여 접근 경로는 남김

## 2. 프롬프트 (User Input)

```text
propensity페이지에서 다음을 수정해줘.
-1번 전략입력 섹션 제거
-2번 평가 항목 입력에서 사용자추가 버튼 제거
-하단에 저장 후 훈련 시작 버튼을 저장 버튼으로 바꾸고 임시저장버튼과 왼쪽의 대사 제거

-평가항목설정 왼쪽의 숫자 2 제거해줘
-카드가 쓸데없이 가로로 넓은 거 같아. 좀 줄여줘.
-저장 버튼을 감싸는 섹션 지우고 딱 버튼만 남겨줘.
-원칙 비율 합계가 100이 아니면 저장 버튼 비활성화 시켜줘.

어 띄워줘. (비활성화 시 안내)
그리고 헤더를 오른쪽으로 옮겨서 중앙 카드의 왼쪽면에 정렬해줘.
추가로 저장 버튼은 왼쪽으로 옮겨서 중앙 카드의 우측면에 딱 맞게 해줘.

페이지 사이드바의 계정 버튼 제거해줘
아니 딱 계정' 버튼만 제거해. 하단의 /account버튼은 남겨두고
```

## 3. AI 응답 요약 (AI Output)

- **1번 섹션 제거**: `PropensityAssessment`(전략 입력) 전체를 페이지에서 제거하고 관련 state/props도 정리
- **2번 사용자 추가 버튼 제거**: 평가 항목 비중 설정 카드에서 “사용자 정의 항목 추가” 버튼 제거
- **하단 액션 단순화**:
  - `임시 저장`/`저장 후 훈련 시작` → `저장` 단일 버튼
  - 왼쪽 안내 문구(대사) 제거
  - 저장 버튼을 감싸던 섹션을 없애고 버튼만 남기도록 컴포넌트 구조 단순화
- **저장 조건 강화**:
  - 활성화된 원칙들의 비중 합계를 계산
  - 합계가 100%가 아닐 때 저장 버튼 비활성화
  - 비활성화 상태에 마우스 호버 시 안내 문구 툴팁(title) 제공
- **레이아웃/정렬**:
  - 평가 항목 카드 폭이 과도하게 넓게 보이는 문제를 `max-w`로 제한하여 중앙 정렬
  - 페이지 상단 헤더와 하단 저장 버튼이 동일한 폭 기준(카드 폭)으로 정렬되도록 페이지 컨테이너 폭을 카드에 맞춤
- **사이드바 계정 버튼 처리**:
  - 사이드바 상단 navItems의 “계정” 메뉴만 제거
  - 하단 `/account` 사용자 버튼은 유지

## 4. 결과 및 적용 (Result)

- 원칙 페이지 UI 변경
  - `src/app/propensity/page.tsx`
    - 1번 섹션(전략 입력) 제거
    - 저장 가능 조건(`totalWeight === 100`) 계산 후 저장 버튼 disabled 연결
    - 페이지 컨테이너 폭을 카드 폭과 동일하게 맞춤(헤더/카드/저장 버튼 정렬)
  - `src/components/propensity/PrinciplesCustomizer.tsx`
    - 헤더 왼쪽의 숫자 배지(2) 제거
    - 카드 폭 축소 및 중앙 정렬(`max-w`)
    - 사용자 정의 항목 추가 버튼 제거
  - `src/components/propensity/ActionBar.tsx`
    - 버튼 1개(저장)만 렌더링
    - disabled 상태 스타일 및 안내 툴팁(title) 추가

- 사이드바 메뉴 변경
  - `src/components/layout/Sidebar.tsx`
    - `navItems`의 “계정” 항목만 제거
    - 하단 `/account` 사용자 버튼은 유지

- 추가적인 수정 사항 / 특이사항
  - 저장 버튼 비활성화 안내는 프로젝트 스타일의 커스텀 툴팁 대신 브라우저 기본 `title`을 사용해 최소 변경으로 구현
  - 비율 합계 계산은 “enabled인 원칙만” 대상으로 합산하여 실제 UX 의도와 일치하도록 함
