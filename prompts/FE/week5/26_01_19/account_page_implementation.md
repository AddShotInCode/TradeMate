# Account Page Implementation (/account)

## 1. 배경 및 목적

- 회원이 자신의 개인정보/보안 설정을 확인·수정할 수 있는 **회원정보 페이지(`/account`)**가 필요
- 제공된 디자인 시안(`tmp_account.html`)을 기반으로 **Next.js(App Router)** 페이지를 구현
- **사이드바 최하단 사용자 이름 버튼**을 클릭했을 때 `/account`로 이동하도록 라우팅 연결
- 회원가입(`/register`)과 동일한 입력 제한/검증 규칙을 회원정보 페이지에도 일관되게 적용

## 2. 프롬프트 (User Input)

```text
이 파일의 디자인을 기반으로 회원정보 페이지(\account)를 만들어줘.
사이드바 하단의 이름 뜨는 버튼 클릭할 때 이동할 수 있게 해줘.
단, 왼쪽의 프로필카드와 security status는 필요없어.
페이지의 모든 내용은 한글로 적절히 변경해줘.

ㄴㄴ계정 메뉴말고 사이드바 최하단에 사용자이름 표시되는 버튼이랑 연결해줘.

이메일 칸은 수정 못하게 비활성화해줘.
생년월일 연도는 무조건 4자리 입력으로 받고 범위는 회원가입 페이지랑 똑같이 해줘.
전화번호, 새비밀번호, 새비밀번호확인 칸의 입력제한조건은 회원가입페이지의 전화번호, 비밀번호, 비밀번호확인 칸과 동일하게 해줘.

어 맞춰줘. 그리고 연도 입력도 월,일처럼 목록버튼으로 해줘.

이름칸이 빈칸이 되면 이름을 입력해주세요 라는 안내 문구 나오게 해줘

사이드바 맨 밑에 있는 사용자이름 뜨는 버튼을 /account로 연결해줘.
```

## 3. AI 응답 요약 (AI Output)

- **페이지 생성**
  - `src/app/account/page.tsx` 신규 추가
  - 기존 화면 스타일(다크/라이트, 카드 레이아웃, 입력 UI)을 프로젝트 톤앤매너에 맞게 적용
  - 좌측 프로필카드/보안상태(aside) 영역은 제외하고, 메인 폼 중심으로 구성

- **라우팅 연결**
  - `src/components/layout/Sidebar.tsx`의 **맨 아래 사용자 이름 버튼**을 `Link`로 바꿔 `/account`로 이동하도록 연결
  - 상단 네비게이션의 “계정” 메뉴는 변경하지 않고(요청사항), 하단 사용자 버튼만 연결

- **입력 제한/검증 규칙(회원가입과 동일하게 정합성 유지)**
  - 이메일: `disabled + readOnly`로 수정 불가 처리
  - 생년월일: 연/월/일 선택형으로 구성
    - 연도 범위: `(현재연도-100) ~ (현재연도)`
    - 연도 선택도 월/일처럼 **드롭다운(목록)**으로 제공
    - 연/월 변경 시 해당 월의 최대 일수 초과하면 `일` 자동 초기화
  - 전화번호: 숫자만 입력 가능 + 최대 11자리(빈 값 허용), 11자리가 아니면 안내 문구 표시
  - 새 비밀번호: 영문/숫자/특수기호 포함, 8자 이상(빈 값 허용)
  - 새 비밀번호 확인: 새 비밀번호와 일치해야 함

- **저장 UX**
  - “변경사항 저장” 클릭 시 위 조건들을 검증
  - 오류가 있는 첫 번째 입력칸으로 포커스 자동 이동
  - 검증 통과 시 저장 완료 메시지 표시

- **추가 UX**
  - 이름이 빈 값이 되면 “이름을 입력해주세요.” 안내 문구 노출
  - 저장 시도 시에도 동일 안내 및 포커스 이동
