# 시뮬레이션 기능 고도화 및 UI/UX 개선

## 1. 배경 및 목적

- 시뮬레이션 기능의 비즈니스 로직(거래 시 보유량 전송, 매도 사유 필수 등)을 완성하고, 사용자 경험을 위한 UI/UX 개선(Smart Resume, Toast 알림, 다크모드 등)을 수행함.
- 종료된 시뮬레이션에 대한 처리(Read-Only, 결과 분석 버튼) 및 재무제표 조회 기간 제한 등 디테일한 요구사항 반영.

## 2. 프롬프트 (User Input)

```text
1. "Rendered fewer hooks than expected" 에러가 발생해. 훅 순서 문제 같은데 확인해줘.
2. API 명세를 보니까 placeOrder 시 balance 필드에 현금이 아니라 현재 보유 주식 수량을 보내야 해.
3. 매도할 때도 매수처럼 사유(comment)를 필수로 입력하게 하고 싶어. 그리고 보유 포지션 목록에서 '청산' 버튼은 없애고 매도 탭을 통해서만 팔게 하자.
4. 재무제표 조회는 2021년부터 시뮬레이션 현재 년도까지만 조회되도록 제한해줘.
5. 평가손익이 음수일 때 마이너스 표시가 안 되고 있어. 색상도 파란색으로 해줘.
6. 모든 alert() 창을 sonner 같은 toast 라이브러리로 변경해서 예쁘게 보여주자.
```

## 3. AI 응답 요약 (AI Output)

- **Hook 규칙 준수**: `OrderForm.tsx`에서 조건부 렌더링 이전에 `useEffect`가 호출되도록 코드를 재배치하여 런타임 에러 해결.
- **API 데이터 포맷 수정**: `placeOrder` 요청 시 `balance` 필드에 `currentHoldings`(종목 보유 수량)을 매핑하여 서버 스펙 준수.
- **매도 프로세스 강화**: 매도 탭에 사유 입력란을 추가하고 필수 검증 로직 적용. '청산' 버튼을 제거하여 사용자가 의도적인 매도 절차를 밟도록 유도.
- **UI/UX 개선**: 재무제표 연도 필터링(2021~), 손익 표기(Color/Sign), 다크모드 대응 등 디테일 수정.
- **알림 시스템 고도화**: `sonner` 라이브러리를 도입하여 시스템 전반의 `alert`를 모던한 `toast` UI로 대체.

## 4. 결과 및 적용 (Result)

- **`src/store/simulationStore.ts`**: API 스펙에 맞춘 데이터 전송 포맷 확립.
- **`src/components/simulation/*`**: 사용자 실수를 방지하고(매도 사유 강제, Alert 제거), 시각적 직관성(음수 컬러/부호, 다크모드)을 높임.
- **`src/services/*`**: API 연동 안정성 확보.
- **라이브러리 추가**: `sonner`를 통한 일관된 알림 UX 제공.
